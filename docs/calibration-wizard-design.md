# Dobot 相机到基座标定向导

日期：2026-10-20。需求来源：Kunyu 提供的 Nova2 固定棋盘七步流程。

## 交付目标

在本仓库中集成已有标定算法，提供可以由操作人员逐步完成的中文本地浏览器界面。操作者不需要手工拼接命令或编辑 CSV。支持中断恢复、左右臂分开标定、实时过程和中间结果展示，以及结果文件导出。

使用现有 Python 工程加标准库 HTTP 服务和本地 HTML/CSS/JavaScript。入口为 `python -m task_skills.run_calibration_ui`，默认仅绑定 `127.0.0.1`，不修改或重启既有执行网关。新增标定依赖单独固定，避免安装整个训练和仿真环境。

## 七步操作

1. **环境与任务准备**：显示依赖检查，创建/恢复会话，选择真实任务或明确标记的模拟演示，设置相机 ID、分辨率、11×8 内角点、30 mm 格长和验收阈值。提示 12×9 是方格数。
2. **相机内参**：上传多张图片或打开本机 OpenCV 相机预览并采集，分配 train/val，展示缩略图、角点覆盖、每图重投影误差和总体 RMS。建议 18–24 train、5–8 val；执行最低 10 train、3 val。此阶段移动棋盘，相机和图像几何设置不变。
3. **固定棋盘**：上传/采集固定板图，确认棋盘已固定且完整可见，执行检测并展示 88 个角点的编号图。0 是内交点，x 指向 1，y 指向 11。确认 normal/reverse，重新检测产生新版本并使下游数据失效。
4. **TCP 角点示教**：左右臂独立记录 robot_id/base_frame/tcp_name/unit；毫米默认且明确显示。点击编号图选择角点，填写 XYZ、train/val，支持 CSV 导入导出、编辑和删除，显示覆盖分布。最低 6 train、3 val，建议 8–12 和 3–5；拒绝重复 ID、共线/狭窄覆盖、NaN 等输入。可选按按钮只发送 GetPose() 读取当前 TCP，必须先确认示教器基座、尖端 TCP、单位；不自动连接、不运动。
5. **拟合**：每臂单独运行，展示当前阶段、日志、PnP RMS、训练/保留点最大误差、逐点残差和坐标轴图、4×4 变换。退出码 0/1/2 分别为通过/运行错误/计算完成超阈值。失败结果可查看但不能标成可用。
6. **像素查询**：在原始分辨率图上点击像素，支持板坐标有符号高度；0 是印刷表面，正负由板 z 轴决定。显示左右臂对应基座的 m/mm 坐标。默认禁用深度模式，只有确认同一光学坐标系注册后允许。图像缩放必须正确换算像素坐标。
7. **独立验收和导出**：输入/导入至少 3 个独立测量点，明确测量方法与独立性确认，显示最大误差、RMS、逐点参考/预测/误差及通过状态。左右臂分别验收。导出 JSON/CSV/图像/会话报告包，包含单位、坐标系、哈希、阈值、版本、证据范围。

## 界面与状态

使用清晰的工业仪器风格：深色导航、浅色工作区、青蓝强调色、橙色待确认、红色失败、绿色通过。左栏是编号步骤及状态，中栏是当前操作、图像和数据表，右栏是前置条件、关键指标、产物和可折叠事件日志。支持键盘操作、中文说明、空状态和有意义的禁用原因。不得只做命令展示或静态样板。

会话及图像保存在被 Git 忽略的 `calibration-data/` 中。长操作后台执行并持久记录阶段、日志、状态和产物；刷新页面可恢复。修改内参、分辨率、棋盘定义/顺序、示教点、robot_id/base/TCP/unit 等上游输入时，基于版本/哈希使所有相关下游拟合和验收失效，不允许复用旧通过标签。任务运行期间避免并发修改依赖或对同一输出写入。

模拟演示必须贯穿显示 `synthetic_only`，生成结果不能被包装为真实现场验收。独立验收参考值不得从同一相机变换自动回填；演示只能在独立模拟任务中展示。

## 项目集成边界

标定实现放入 `task_skills/calibration/`，复用提供的 `calibrate.py`、`table_calibration.py`、`nova2_read_pose.py`，仅作包导入等必要调整。使用明确的相机到左右臂基座变换对象供原子技能的感知侧调用，并检查相机 ID、robot_id、单位、输入哈希和有效状态。不得将外参自动写入现有示教位姿、scene_config 或 chemistry profile，也不调用运动驱动。README 增加一键启动和可选虚拟环境脚本。

本次开发/测试仅使用离线数据与模拟 socket，不连接真实机械臂、夹爪或相机，不发送运动、使能、清错、坐标系切换或串口命令。产品的相机采集和 GetPose 只由操作者显式触发。源文件、旧项目、现有运行服务、数据库和凭据保持原状。

## 验收证据

- 原有 15 项标定几何/协议测试经包迁移后通过，合成桌面流程跑通并保留 synthetic 标记。
- 新测试覆盖会话恢复、步骤前置条件、左右臂隔离、上游修改失效、失败阈值、单位/非有限数/重复点、产物路径约束与只读 GetPose。
- 浏览器实际走通演示和关键失败恢复，保留截图、HTTP 证据和测试命令结果。

- 独立代码审查，修复实质问题后复审。离线成功不等于真实相机内参、TCP 或真机精度验收。

## 2026-10-20 独立审查补充约束

第二轮修复必须读取运行目录的 `review-1.json`、`python-review-1.md` 和 `js-review-1.md`，包括专家报告中晚于汇总文件完成的发现。

有效性检查必须从当前实际保存的示教点内容、机械臂元数据和当前内参原图字节重新计算哈希，不能只信任会话内的 `points_hash` 等缓存字段。独立 Python 审查已复现：直接改动保存的 `points[0].x` 而不改缓存哈希时，旧拟合/验收依然被判有效。这也必须修复并补回归，与内参原图内容变化检查一起验收。

导出包必须包含内参矩阵、畸变、相机几何/标识以及复用所需的完整输入/结果，能够在原会话目录以外重现像素到基座映射。前端空输入不能被数值零替代；跨任务响应、跨臂草稿和失效后的查询显示必须有针对性回归。后台任务的持久化提交失败必须落入可恢复的终态，不能永久停留 running。
