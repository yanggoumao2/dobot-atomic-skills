## 流程可行性

有线连接用于传输数据、SSH远程操作、查看训练日志和取回checkpoint。训练时从旧主机本地磁盘读HDF5。可以通过同一路由器/交换机接入，也可以两机直连。

直连时先查看双方网卡与现有网段，再选择独立网段。若192.168.50.0/24未占用，可用192.168.50.1与192.168.50.2，掩码255.255.255.0。该专用链路可不填默认网关。保持机器人192.168.5.x网络配置。静态地址、SSH与防火墙配置等连接后按实际操作系统执行。

网卡协商速率与数据量决定传输时间。1 Gbit/s理论上限125 MB/s，100 Mbit/s理论上限12.5 MB/s，实际还受硬盘限制。数据复制到主机后，训练速度由主机计算和本地I/O决定。

## 任务1　确认数据集交付

- [x] 使用项目现有ACT转换入口，输出48个HDF5、映射清单、质量报告及固定划分。
- [x] 检查48个文件的数据键、尺寸、有限值、图像顺序和同行配对属性。每条检查首末源样本的状态、动作及双视角图像映射，并通过现有NumPy加载函数检查首末窗口和padding。
- [x] 保存必要的训练加载代码副本和只用训练集计算的归一化统计，便于主机接续。

## 任务2　连接后读取主机配置

- [ ] 查看主机CPU、内存、系统、空闲磁盘、网卡连接速率。
- [ ] 查看显卡型号、显存、驱动；NVIDIA机器读取 `nvidia-smi`，再检查PyTorch能否识别CUDA并执行小张量计算。
- [ ] 按实际GPU架构与驱动选择兼容的PyTorch/torchvision组合。较老GPU可能需要兼容的历史版本；安装命令在确认硬件后确定。
- [ ] 验收结果记录为主机配置与可用训练设备。CPU环境可用于加载及流程检查，正式训练耗时通过测速判断。现有上游ACT训练代码使用 `.cuda()`，CPU运行需要适配设备路径。

## 任务3　传输与训练入口接入

- [ ] 启用适合主机系统的远程访问。Linux优先SSH；Windows可使用OpenSSH或现有远程工具。
- [ ] 传输整个ACT数据集与训练支持代码到主机本地磁盘，完成一次传输校验，记录实际传输时间。
- [ ] 获取并固定上游ACT提交。接入本项目数据加载器，使用数据集的38/10划分和训练集统计。
- [ ] 为当前任务建立训练入口，传入数据目录、checkpoint目录、相机顺序、device、batch_size、chunk_size、seed与总optimizer steps。训练配置通过实际入口保存。
- [ ] 上游 `imitate_episodes.py` 的任务路由会导入ALOHA或仿真环境。主机训练入口应直接组装ACTPolicy与训练循环，按本项目HDF5加载，减少机器人运行环境依赖。
- [ ] 验证集使用固定起始帧集合，例如每条的0%、25%、50%、75%位置，固定验证采样保证checkpoint之间可比较。训练集仍随机采样起始帧。

## 任务4　训练配置与小规模测速

初始候选配置采用ResNet18骨干、hidden_dim=512、dim_feedforward=3200、encoder 4层、decoder 7层、8个注意力头、KL权重10、学习率1e-5、chunk_size=30。沿用双视角与14维格式。上述为方案选择，显存需求尚待实测。

- [ ] 先用batch_size=1完成一次前向、反向及checkpoint保存/重新加载。检查loss有限、padding正确，确认图像仅在ACTPolicy中执行一次ImageNet归一化。
- [ ] 在主机记录100～200个optimizer steps的耗时、显存峰值与GPU利用率，包含少量预热。
- [ ] 有显存余量时提高batch至2、4，显存足够再尝试8。较小显存先用batch1；仍不足时再评估混合精度或调整输入分辨率。改变分辨率须形成明确的训练预处理配置。
- [ ] 按实测step耗时估算1000步与10000步的训练时间，决定旧主机是否满足可接受时长。训练预算按optimizer steps记录。

## 任务5　初版训练与评估

- [ ] 先跑1000步，观察训练/验证重建误差及KL项，保存best、last与定期checkpoint。
- [ ] 流程稳定后以10000步为首轮预算，每250步固定验证，每1000步保存checkpoint。若验证或策略平滑性仍有改进，增加训练预算。
- [ ] 第一轮使用seed0；调参保持验证集一致。训练时记录归一化关节动作误差、夹爪开闭误差与固定验证窗口的曲线。
- [ ] 取回best checkpoint、训练集统计、模型参数、数据映射清单、软件版本、训练日志和step耗时。
- [ ] 真机测试另按当前Dobot手册接入推理。按完整抓取、插入、松爪、撤离后稳定统计任务成功率，并记录失败阶段。当前48条验证集主要覆盖现有固定杯位采集场景。

## 连接后的决策

GPU能够运行兼容PyTorch且batch1反向通过，就有继续实测训练效率的基础。主机若只有CPU、GPU驱动不兼容或显存不足，需要据具体型号与测速结果重新选择环境或训练配置。当前可确认有线传输与远程训练架构可行，计算能力结论待硬件读取与小规模测速。
